# Action and control hierarchy

## Action levels

| Level | Use | Treatment |
|---|---|---|
| Decision-primary | The current state’s essential, valid next step | Large/full-width mobile treatment or clear desktop primary placement. |
| Standard primary | Important page-level completion not competing with another decision | Standard primary Button. |
| Secondary | Reversible/supporting action | Secondary/outline treatment. |
| Inline/contextual | Detail, filter, edit or low-friction task | Text/inline or compact control with a 44px target on mobile. |
| Icon-only | Familiar, compact auxiliary action | Lucide, accessible label and 44px target. |
| Destructive/overflow | Irreversible or low-frequency action | Deliberately separated, confirmation where consequence warrants it. |

Examples: a Customer’s valid booking/payment CTA is decision-primary; share/favorite are secondary. An Owner’s pending request acceptance is primary and rejection is destructive; “عرض التفاصيل” is secondary. An ineligible payout is disabled with a reason—not a primary CTA. Admin review decision actions are prominent only in the selected review context.

## Control sizes

| Size | Use |
|---|---|
| Comfortable | Mobile primary decisions, search and high-frequency fields; >=44px target. |
| Standard | Default forms/actions; >=44px target on mobile. |
| Compact-desktop | Admin filters, tables and dense operations where readability and keyboard access remain intact. |

No one-off control height is introduced outside component contracts.
