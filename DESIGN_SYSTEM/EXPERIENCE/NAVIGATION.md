# Navigation authority

Navigation follows destination frequency and user job—not visual symmetry.

| Role | Current navigation | Destination authority — RECOMMENDED |
|---|---|---|
| Customer | Bottom navigation: Explore, Favorites, Bookings, Account; property/booking/auth/support/wallet are contextual modal or full-screen flows. | Explore and Trips/Bookings deserve persistent access. Favorites remains top-level only while it has a supported value proposition. Payment and chat are booking-contextual, not top-level. |
| Owner | Bottom navigation: Home, Bookings, Wallet, Properties, Messages; Calendar, Profile, Disputes and notifications contextual. | Top-level destinations should answer active work frequency. Calendar/property details belong inside property operations; Profile and disputes remain contextual unless live usage proves otherwise. |
| Admin | Desktop horizontal operations navigation: Overview, Verification, Properties, Payouts, Disputes; detail views contextual. | Preserve operational-domain navigation, filters/search and back-to-queue context. Do not add mobile bottom navigation. |

Navigation requirements: every contextual view has a clear return path; selected state is explicit; a destination is not top-level merely because it exists; actions may open contextual detail but cannot strand the user in a dead end.
