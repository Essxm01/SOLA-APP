# Shared experience principles

| Principle | Authority |
|---|---|
| Clarity over decoration | State, next action and consequence are visible before decoration. |
| One primary action | A decision area normally has one visually dominant next action. |
| Progressive disclosure | Detail appears when it helps the current decision, not all at once. |
| Contextual actions | Action visibility responds to canonical business state and role. |
| No fake capabilities | No button implies an unsupported, unavailable or invalid action. |
| Error is not empty | Request failure never becomes a credible empty list, zero balance or zero metric. |
| State before style | Loading, error, disabled and business-state correctness take priority over motion/decor. |
| Role relevance | Information must help the current role decide or complete work. |

These principles complement visual v2.0 tokens. They do not create new product or financial rules.
